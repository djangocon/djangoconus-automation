# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands
- Build: `just build` (docker compose build)
- Run: `just up` (start with docker compose)
- Test: `just test` (run all tests)
- Single test: `docker compose run --rm --no-deps web pytest tickets/tests/test_models.py::TestClassName::test_method`
- Lint: `just lint` (runs pre-commit on all files)
- Pre-commit: `just pre-commit` (runs pre-commit hooks)

## Code Style
- **Formatting**: Black-compatible (120 char line length)
- **Linting**: Ruff with rules 'B', 'E', 'F', 'I', 'W', 'B9'
- **Imports**: Standard library → Django/third-party → Local modules (sorted alphabetically)
- **Naming**: snake_case for variables/functions, PascalCase for classes
- **Testing**: pytest with django_db marker for DB tests, fixtures in conftest.py
- **Error Handling**: Use try/except with specific exceptions, atomic transactions for DB operations
- **Django Patterns**: Class-based views preferred, model fields have descriptive names

## Project Structure
- Django apps are organized functionally (tickets, sendy, titowebhooks)
- Management commands in app/management/commands/
- Tests should be in app/tests/ directory

## Production

- **SSH host**: `ssh defna-node1`
- **Public URL**: https://automation.defna.org
- Deployed via **Coolify** (Docker). There is no deploy descriptor in this repo — production env vars are set in the Coolify UI, not in version control.

Container names are generated by Coolify and **change on every deploy** (they embed the commit SHA), so always look them up rather than hardcoding:

```bash
ssh defna-node1 'docker ps --format "{{.Names}}\t{{.Image}}\t{{.Status}}"'
```

The web container runs `/src/start-web.sh`, the worker runs `/src/start-worker.sh`; identify them with:

```bash
ssh defna-node1 'docker inspect -f "{{.Name}} {{.Config.Cmd}}" $(docker ps -q)'
```

Run Django management commands in the web container (app lives at `/src`, deps via uv):

```bash
ssh defna-node1 'docker exec -w /src <web-container> uv run --no-sync manage.py shell -c "..."'
```

Notes:
- Prod runs with `DEBUG=False`. Before the `LOGGING` config was added, 500 tracebacks were discarded entirely — if logs look suspiciously empty, check that `LOGGING` is still configured in `config/settings.py`.
- No Sentry project is wired to this app.
- Never print secret env values when inspecting containers — list names only (`docker exec <c> env | cut -d= -f1`).
